# TEST71 manual WhatsApp verification

Customer chooses WhatsApp or existing SMS OTP. WhatsApp creates a 16-character random one-use request code, bound to the canonical customer number and trusted device, with a 15-minute expiry. Customer controls opening and sending the message to the unique active Owner's existing number (chosen by the user). Admin must inspect the actual WhatsApp sender profile/number and enter that number plus the received code; neither field is prefilled. Opening WhatsApp never grants access.

Backend requires active Super Admin, pending current challenge, unconsumed matching code, canonical sender number and unpaused customer. Approval, challenge consumption and append-only verification evidence are atomic. Session issuing and validating recognize explicit WHATSAPP_MANUAL evidence, while otp_owned and SMS evidence retain their original meaning. Manual evidence is invalid after revocation, a new request, or a customer phone change. Private challenge/evidence tables have RLS and no customer/staff table grants. A customer can have at most ten recent WhatsApp challenges per 15 minutes; a customer advisory lock serializes creation. Existing notification routing and pause/revoke controls are reused.

Verification: 16/16 targeted frontend/SMS/approval tests passed. Live database rollback checks passed for correct approval/session validation, canonical customer identity, pending lock, actual sender mismatch, wrong/expired/consumed code, unauthenticated approval, generic checkbox bypass, device mismatch, pause/revoke and changed registered number. Tests roll back approvals, sessions, evidence and notification outbox rows. No test WhatsApp message was sent.

Security advisors were reviewed. RLS-without-policy notices on the two private tables are intentional deny-all. Public request EXECUTE is intentional for share-token-bound pre-login requests; authenticated approval EXECUTE is protected by the existing Super Admin assertion. Other project-wide findings predate this change and were not altered. Advisor reference: https://supabase.com/docs/guides/database/database-linter

This is personal WhatsApp manual verification, not automatic WhatsApp OTP or a WhatsApp Business API integration. No MSG91/Twilio recharge, payment, business-document upload or calling-provider change was made. Real sender delivery and approval using two phones remain a user-assisted acceptance check. Codespace deployment must serve the updated scripts before the option appears.
