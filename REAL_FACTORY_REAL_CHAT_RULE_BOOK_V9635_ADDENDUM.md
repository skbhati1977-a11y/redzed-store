## LOCKED CI-HISTORY / AVERAGE-RATE / UNIVERSAL FIELD DISPLAY RULES — V9641

109. Customer ALL AVG is defined from FINAL CI purchase history only. Any valid FINAL CI for the same resolved Party/Customer identity is included regardless of whether business originated through Real Chat -> Requirement -> PI -> CI or through a direct physical/shop CI flow.
110. Requirement alone is never purchase history. PI alone is never purchase history. Draft, awaiting, expired or cancelled PI is excluded. Draft/cancelled/non-final CI is excluded. A commercial transaction enters permanent ALL AVG history only when it is a valid FINAL CI.
111. FINAL CI history average uses sale-line commercial value, not freight/GST/round-off invoice overhead: historical value = sum of FINAL CI net sold quantity x authoritative final/net line rate. Valid returned quantity reduces the effective CI quantity/value for average-rate purposes. Grand Total containing freight/tax is not the per-piece average-rate source.
112. Customer-to-CI identity resolution is server-side and data-mode scoped. Preferred mapping order is explicit CI snapshot contact_customer_id/customer link, then authoritative normalized customer/buyer mobile match, then an exact normalized customer/buyer name fallback only when that name is unambiguous/unique on both sides. Ambiguous identity must not be guessed or silently merged.
113. ALL AVG is shown in the REDZED COLLECTION header as a small bordered metric. When valid CI history exists and an active Requirement exists, displayed ALL AVG is a live projected blended average: (FINAL CI historical net value + current Requirement net value) / (FINAL CI historical net qty + current Requirement qty). This projection is display-only and never writes the Requirement into purchase history before CI.
114. If the customer has no valid FINAL CI history, ALL AVG remains visible and displays an em dash (—), even if the customer has a current Requirement. Current Requirement does not become historical purchase merely to manufacture an ALL AVG value.
115. REQ AVG is the current Requirement weighted net average per piece: current Requirement net amount / current Requirement qty. It follows the current confirmed Requirement in chat and follows the live draft only while the Requirement edit window is open. BACK TO CHAT discards unsaved draft metrics and restores confirmed Requirement metrics.
116. Lifecycle behavior: ALL AVG remains a customer-history metric in the Collection header; during an active Requirement it may show the projected blended value, when Requirement converts to PI or closes without CI it reverts to FINAL-CI-only history, and after a new FINAL CI it naturally updates from the enlarged CI history. REQ AVG / REQ QTY / REQ AMT are Requirement-stage metrics and hide only at the explicitly terminal Requirement lifecycle stage (PI conversion, CI final, closed/no-response/cancelled as applicable).
117. UNIVERSAL FIELD DISPLAY CONTRACT: once a field/metric is created for an applicable UI stage, the field itself must be rendered. If authoritative current/legacy data exists, show the actual value. If the record/value is missing, unresolved or not yet available, show an em dash (—). Do not hide a field merely because data is absent, and do not substitute numeric 0 for missing data. Numeric 0 is shown only when an authoritative record exists and its actual value is zero.
118. The universal dash/display contract applies to future generated fields as the default rule unless a separately locked lifecycle/business rule explicitly says the field is not applicable and should hide at that stage.
119. STABILITY CONTRACT: customer Real Chat/Collection UI refresh logic must use bounded finite retries/refreshes for delayed DOM/server readiness. Do not add unbounded MutationObserver repaint loops, recursive indefinite timers, or continuous DOM-write observers for these metrics. A bounded retry must stop after its defined attempt/time limit and leave the last authoritative state/dash visible rather than freezing/stucking the page.
120. V9641 safe implementation remains isolated from the stable production customer/staff routes until tested. Server CI-history resolution is read-only for this display feature; it does not alter FINAL CI, PI, stock, customer master, or existing accounting records.
